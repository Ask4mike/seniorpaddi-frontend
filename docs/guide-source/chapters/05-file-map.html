The rule of thumb

If you want to change...Look in
The words on a pagelocales/en.json and locales/yo.json
The layout or HTML of a pageviews/ (the page) and views/partials/ (shared pieces)
Colours, fonts, spacing, card stylessrc/styles/input.css, then npm run build:css
What happens when a page opens or a form is sentsrc/routes/
A rule used in several places (seats, SMS, dates)src/services/
What is stored in the databasesrc/models/ and a new file in src/migrations/
Picturespublic/images/ (and record them in IMAGE_CREDITS.md)
A small in-browser behaviour (pop-ups, password eye)public/js/
Important

There is no controllers/ folder in this project. In many Express projects the code that answers a request lives in "controllers". Here it lives directly inside the route files in src/routes/, and shared logic lives in src/services/. When other tutorials say "controller", read "the function inside router.get(...) or router.post(...)".

Things to know
  • .gitignore contains the line images/, which tells Git to ignore every folder called images, including public/images/. The pictures already in Git stay tracked, but a new picture you add there will be silently left out of commits unless you use git add -f (chapter 10 shows how). If that line was only meant for docs/images/, change it to /docs/images/.
  • public/images/hero.png is not used by any page.
  • public/images/README.md is partly out of date (it says no WebP versions exist and that the hero photo has no description; both have since changed). IMAGE_CREDITS.md is the current record.
What you learned
  • src/ is the server, views/ are the pages, public/ goes to the browser untouched, locales/ holds the words.
  • Route files do the "controller" job in this project.
  • Never edit public/css/main.css or anything in node_modules/ by hand.
