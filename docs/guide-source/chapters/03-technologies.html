JavaScript and Node.js

JavaScript is a programming language. It started in web browsers, which is why the little scripts in public/js/ are JavaScript. Node.js is a program that runs JavaScript on an ordinary computer or server, outside a browser. All of src/ runs in Node.js. The project says it needs version 20 or newer:



Two JavaScript ideas you will see everywhere in this project:


    
  
  • require('...') loads another file or package so you can use it, like borrowing a tool from a shelf. module.exports = ... is how a file puts its tools on the shelf.
    • 
  
  • async and await: talking to the database takes time, so await means "wait here for the answer before carrying on".
    • 




npm and package.json


npm (Node Package Manager) comes with Node.js. A package is code someone else wrote and shared, like Express. package.json lists the packages SeniorPadi needs and gives names to its commands ("scripts"). npm install downloads the packages into node_modules/; npm run dev runs the script called dev.




  • This script uses cross-env to set DB_TARGET=local (works on Windows, Mac and Linux alike) and nodemon to restart the site when a .js or .json file changes.



Express


Express is a web framework: a ready-made skeleton for a web server. You tell it "when someone asks for this address, run this function". Those instructions are called routes. Express also runs middleware, functions that every request passes through on its way to a route, like security guards in a corridor.


Where: src/app.js builds the app; src/routes/ holds the routes; src/middleware/ holds the middleware.




    
  
  • Each line plugs a file of routes into the app. They are tried top to bottom until one matches the address.
    • 
  
  • The admin routes are plugged in at /admin, so router.get('/events') inside admin.js answers /admin/events.
    • 




EJS (Embedded JavaScript templates)


EJS lets you write an ordinary HTML page with special tags where data should go. The server fills in the gaps and sends plain HTML. Chapter 6 is all about EJS.


Where: every file in views/. It is switched on in src/app.js:




  • "Use EJS for pages" and "the pages are in the views folder". So res.render('home') means views/home.ejs.



PostgreSQL and the pg driver


A database stores information permanently, in tables (like spreadsheets): a Users table, an Events table and so on. Each row is one thing (one user); each column is one detail (their phone number). PostgreSQL ("Postgres") is the database program SeniorPadi uses. It runs separately from the website: on your computer while you develop, or on Neon (a Postgres host in the cloud) for the live site. pg is the package Node uses to talk to it.




  • A "pool" is a small set of open connections to the database that get reused, which is faster than connecting for every request.



Sequelize, models and migrations


Sequelize is an ORM (object-relational mapper): it lets you work with tables using JavaScript instead of writing database commands (SQL) by hand. A model is the JavaScript description of one table.




Reading data then looks like this (the Home page asking for the next four published events):




    
  
  • where: only published events that start after now (Op.gt means "greater than").
    • 
  
  • include: [Organization]: also fetch the organization each event belongs to.
    • 
  
  • order and limit: soonest first, at most four.
    • 



A migration is a small file that changes the shape of the database, for example "create the Organizations table". They are kept in date order in src/migrations/ and each one runs only once. SeniorPadi runs new migrations by itself every time it starts (src/services/migrate.js), so you rarely run them by hand. The Sequelize CLI (command-line interface) can also run them: npm run db:migrate. .sequelizerc tells it where things are.





Sessions: express-session and connect-pg-simple


The web forgets you between requests. A session is how the site remembers you: after you log in, the server stores userId in a session and gives your browser a cookie (a small label the browser sends back with every request). express-session handles this, and connect-pg-simple stores sessions in the database so they survive a restart.




    
  
  • httpOnly: page scripts cannot read the cookie (safer).
    • 
  
  • maxAge: 30 days, so seniors don't have to log in often.
    • 




bcrypt (password hashing)


Passwords are never stored as typed. bcrypt turns a password into a hash, a scrambled string that cannot be turned back. At log-in, bcrypt checks whether the typed password produces the same hash.





csrf-sync (form protection)


CSRF (cross-site request forgery) is a trick where another website secretly submits a form to SeniorPadi using your logged-in browser. To stop it, every form carries a secret token that only the real page knows, and the server rejects forms without the right one.




Warning
Every <form method="post"> you add must include this hidden _csrf line, or submitting it shows "This form has expired".



express-rate-limit


Limits how many times someone can try something in a period of time, so nobody can guess passwords by trying thousands.




  • Log in: at most 10 tries every 15 minutes. Sign up: 5 an hour, and so on.



dotenv and environment variables


An environment variable is a setting given to a program from outside its code, such as the database address or a password. Keeping them outside the code means secrets never end up on GitHub. dotenv reads them from a file called .env in the project folder; the code then reads them as process.env.NAME.





Uploads: multer and Cloudinary


multer receives files sent from a form (profile pictures, ID documents, the welcome video) and keeps them in memory. Cloudinary is an online picture and video store; src/services/cloudinary.js sends the files there. If Cloudinary is not set up, that same file saves uploads on your computer instead (in public/uploads/ and storage/ids/, both ignored by Git).





Brevo (SMS and email) and Google Translate


These are outside web services the server calls over the internet with fetch (no extra package). Brevo sends the confirmation and reminder texts and emails; Google Cloud Translation translates event titles and descriptions into Yorùbá. Both are optional: without keys, messages are printed in the terminal instead, and event text stays in English.





node-cron (scheduled jobs)


Runs a function on a timetable, written in "cron" format. SeniorPadi sends reminders every morning at 8:00 and closes finished events every hour, in Lagos time.




  • '0 8 * * *' reads as "minute 0, hour 8, every day". '0 * * * *' is "minute 0 of every hour".



qrcode


Draws a QR code picture as SVG. Each registration has a QR code staff can scan to mark someone as arrived; it is always optional.





Socket.IO (live chat)


Normally the browser has to ask before the server can answer. Socket.IO keeps a line open between them, so the server can push a new chat message the moment it arrives. It shares the same login session as the website. The plain message form still works if it fails.





Tailwind CSS


CSS (Cascading Style Sheets) is the language for how a page looks: colours, sizes, spacing. Tailwind CSS is a CSS tool built around small ready-made class names such as text-lg (large text) or rounded-full (fully rounded corners), which you write straight into the HTML. You edit src/styles/input.css; the Tailwind CLI reads it plus every template, and writes the finished public/css/main.css.




    
  
  • @source tells Tailwind which files to scan for class names (the views and the browser scripts).
    • 
  
  • Brand colours and the font are set in an @theme block further down. Chapter 9 shows it.
    • 




Font Awesome and the Outfit font


The small icons (phone, calendar, lock) come from Font Awesome, loaded from a public CDN (a fast file server on the internet), so icons need an internet connection. The text font, Outfit, is stored in the project itself (public/fonts/).





Jest and supertest (tests)


A test is a small program that uses the site and checks it behaves correctly. Jest runs the tests in tests/; supertest lets a test send requests to the app without a browser. Run them with npm test. They need their own empty database (TEST_DATABASE_URL) because they wipe it.





Git, GitHub, Render and Neon


    
  
  • Git keeps the history of every change, so you can always go back. A commit is a saved snapshot; a branch is a separate line of work.
    • 
  
  • GitHub stores the Git history online and is where pull requests are reviewed and merged.
    • 
  
  • Render runs the live website. render.yaml tells it how.
    • 
  
  • Neon runs the live PostgreSQL database.
    • 




What you learned

    
  
  • The server is JavaScript running in Node.js, organised by Express, with pages written in EJS.
    • 
  
  • Data lives in PostgreSQL; Sequelize models describe tables, and migrations change them.
    • 
  
  • Sessions, bcrypt, CSRF tokens and rate limits keep accounts safe.
    • 
  
  • Tailwind builds public/css/main.css from src/styles/input.css.
    • 
  
  • Brevo, Cloudinary and Google Translate are optional add-ons; the site runs without them.
