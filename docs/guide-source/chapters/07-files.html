Chapter 7File-by-file walkthrough

A reference for the important files: what each one does, what goes in and what comes out, which files it talks to, and the key lines in plain English. Small, similar files are grouped in tables.

How to read the connection boxes

Used by lists the files that load or call this one (if you change it, check those). Uses lists the files this one depends on. Nearly every server file also uses src/models/index.js to reach the database; that is only mentioned where it matters.

Starting up

src/server.js

What and why: the very first file that runs (npm start runs node src/server.js). It does all the set-up so nobody has to type set-up commands, then starts the web server. Chapter 2 walks through it.

Receives: settings from .env. Sends: nothing; it starts the server and prints progress in the terminal.

Used bypackage.json scripts (start, dev), start-windows.batUsessrc/services/startup.js, src/models/index.js, src/services/migrate.js, src/app.js, src/sockets/index.js, src/services/cron.js

src/app.js

What and why: builds the Express app. The order of the lines here is the order every request is handled in, so this is the file to read to understand the request path.



    
  
  • express.static: if the address matches a file in public/, send that file and stop.
    • 
  
  • express.urlencoded: read submitted form fields into req.body.
    • 
  
  • sessionMiddleware, locals, addCsrfToken, csrfProtection, requirePasswordChanged: the middleware, in order (next section).
    • 



After the routes come two "catch-all" handlers: a 404 page for addresses nobody answered, and an error page for anything that crashed (with a special message when a form's security token has expired).


Used bysrc/server.js; every test file in tests/ (they load the app without starting a server)Usessrc/config/session.js, src/middleware/*, every file in src/routes/, views/error.ejs





src/config/database.js


What and why: decides which database to use and whether it needs an encrypted (SSL) connection. Keeping it in one place means Sequelize, the migration tool and the session store always talk to the same database.




Used bysrc/config/config.js, src/config/session.js, src/scripts/checkDb.js, src/scripts/seed.jsUsesthe .env settings





src/config/config.js and .sequelizerc


config.js turns the result of database.js into Sequelize settings (always store times in UTC, small connection pool). .sequelizerc tells the Sequelize CLI where config.js, the models and the migrations are.


Used bysrc/models/index.js, the sequelize-cli commands (npm run db:migrate)Usessrc/config/database.js





src/config/session.js


What and why: sets up login sessions, stored in a session table in the same database (created automatically). It lives in its own file because both Express and live chat need the very same session.


Used bysrc/app.js, src/sockets/index.jsUsessrc/config/database.js, packages express-session, connect-pg-simple, pg





src/services/startup.js and src/services/migrate.js


startup.js holds the set-up steps server.js calls: check settings (and warn about missing optional ones), wait for the database, add the default welcome-guide text, create the first admin from ADMIN_* settings, and rebuild the stylesheet if it is missing. migrate.js runs any migration files that have not run yet (it records finished ones in a table called SequelizeMeta) and recreates any table that has gone missing. It never deletes data.




  • The first admin is only created if the phone number is valid and the password has at least 8 characters.


Used bysrc/server.js (both); migrate.js also by src/routes/admin.js (System page), src/scripts/seed.js, src/scripts/createAdmin.jsUsessrc/services/phone.js, locales/*.json, src/migrations/*





Middleware



src/middleware/locals.js


What and why: runs on every request. It looks up the logged-in user from the session, picks the language, and puts shared things on res.locals so every template can use them (currentUser, t, formatDate, flash...). It also creates req.flash() for one-time messages.




    
  
  • A logged-in person's language comes from their account; a visitor's from their session; otherwise English.
    • 
  
  • req.t(key) is the translation function routes use; templates get the same function as t.
    • 



Used bysrc/app.js (so, every page)Usessrc/models (User, Notification), src/services/i18n.js, src/services/dates.js





src/middleware/auth.js


What and why: four "gatekeepers" that routes put in front of pages:


FunctionLets you through only if...

  
requireAuthyou are logged in (otherwise: remembers the page and sends you to /login).

  
requireAdminyou are staff (otherwise: "not allowed" page).

  
requirePasswordChangedyou don't need to change a password a staff member reset.

  
requireVerifiedyou are a senior whose ID was approved (for Find seniors and messages).




Used bysrc/app.js and every file in src/routes/Usesviews/error.ejs





src/middleware/csrf.js


Creates the secret form token (csrfToken in templates) and rejects POST requests without it. Upload forms send the token in the address instead, because the file has not been read yet when the check runs.


Used bysrc/app.jsUsespackage csrf-sync

Routes


Each route file creates a router, attaches functions to addresses with router.get or router.post, and is plugged into the app in src/app.js. Inside each function, req is the request (what came in) and res is the response (what goes back).

Services (the rules)



src/services/capacity.js


What and why: everything about seats. Its register() function makes sure an event can never be overbooked, even if two people press Register for the last seat at the same moment. It does this with a database transaction (a group of steps that all happen or none do) and a lock on the event row (others wait their turn).




It also works out the tags shown on events ("Almost full" when 5 or fewer places are left, "Closes in X days" when 5 or fewer days are left) in eventState().


Used bysrc/services/registration.js, src/routes/events.js, src/routes/admin.js; tested by tests/capacity.test.jsUsesmodels Event, Registration; src/services/dates.js





src/services/registration.js


Calls capacity.register(), turns a failure reason into a message key (full, closed, already), and on success sends the confirmation SMS/email with the ticket number. Also has safeNext(), which only allows redirects to SeniorPadi's own pages.


Used bysrc/routes/events.js, src/routes/public.js, src/routes/verify.jsUsescapacity.js, notify.js, dates.js





src/services/notify.js


Sends email and SMS through Brevo. The words come from locales/ (keys ending in .sms, .email, .subject) in the person's language; emails are wrapped in views/emails/layout.ejs. In "dry run" mode (no Brevo key, or NOTIFY_DRY_RUN=true) messages are printed in the terminal instead. A failed message is logged and never stops a registration.


Used byroutes public, account, admin; services registration, cron, removal, verificationUsesi18n.js, audit.js, views/emails/layout.ejs

Models (the database tables)



src/models/index.js


What and why: connects to the database, loads all 18 models, and declares how tables relate (an Event belongs to an Organization; a User has many Registrations). Everything else gets models from here: const { User, Event } = require('../models').




Used byalmost every file in src/, plus the tests and scriptsUsessrc/config/config.js, every other file in src/models/





src/models/user.js


The Users table. Seniors and staff are both users; role tells them apart. paranoid: true means deleting a user only marks them deleted (a "soft delete"), so history stays correct. It adds three helpers you will see in templates and routes:




Used bysrc/models/index.js (and through it, everything)UsesSequelize; the table itself is created by src/migrations/20260927000001-create-users.js and later migrations





src/models/event.js and src/models/registration.js


Event holds what an event is (title, description, picture, start/end, place, category, capacity, volunteers, deadline, status). Its six categories are listed once and reused everywhere: fitness, faith, learning, skills, social, health.


Registration is one person's place at one event, as attendee or volunteer, with a status (registered, cancelled, attended, no_show), a QR token and a ticket number like SP-7K3QX9 (no 0/O or 1/I/L, so it can be read out on the phone).


Used bysrc/models/index.js; heavily by routes/events.js, services/capacity.js, routes/admin.jsUsesSequelize

Views (the pages)



views/partials/header.ejs and views/partials/footer.ejs


What and why: the top and bottom of every page (chapter 6 explains the layout options). The header loads the font, the icons, /css/main.css?v=ui5 and three scripts; draws the skip link, the thin loading bar, the one-line top bar and the menu; and opens <main>. The footer closes <main>, draws the dark footer with four links, adds the log-out pop-up for logged-in people and loads two more scripts.


Used byevery page in views/Usespartials seniorNav, nav (staff), langToggle, flash, confirmLogoutModal; public/css/main.css; public/js/phone-input.js, top-loader.js, ui.js, swipe.js, dialog.js





views/auth/login.ejs


The "Welcome Back" log-in page: on large screens a colourful art panel on the left and a frosted card with the form on the right, with a small trust strip under it. It is a full-screen page (pageLayout: 'auth').


Receives: error, phone, after from the route. Sends: POST /login with _csrf, registerEventId, next, phone, password.




  • data-busy-text is read by public/js/ui.js to show "Logging you in..." with a spinner while the page loads.


Used bysrc/routes/public.js (GET and POST /login)Usespartials header, footer, langToggle, flash, phoneInput, ui/passwordInput; CSS classes auth-frame, auth-art, auth-card, btn-glow





views/auth/signup.ejs


"Create your account": the form on a white panel with a warm beige picture panel beside it. Fields, in order: full name, phone, email (optional), password, confirm password, and the "I am 60 or over" checkbox. Each field shows its own error from the route's errors object.


Things to know
"Confirm password" has no name, so the server never receives it. It is checked only in the browser by public/js/ui.js (the "Passwords match" tick). Without JavaScript nothing compares the two boxes. This was deliberate, to avoid changing the server.


Used bysrc/routes/public.js (GET and POST /signup)Usespartials header, footer, langToggle, flash, phoneInput, ui/textInput, ui/passwordInput; public/images/illustrations/elders-chat.svg





views/home.ejs


Home, in four sections: the hero (its own top bar, a big headline, the arch-cropped photo, the trust words, the number of upcoming events and the white "Find events" button), the three choices (Find events, Find seniors, Call), Events near you (the cards) and How it works.


Receives: upcoming (up to 4 events), plus the shared variables. The greeting uses currentUser.firstName() when someone is logged in.


Used bysrc/routes/public.js (GET /)Usespartials header (with pageLayout: 'hero'), footer, seniorNav, langToggle, eventTile; public/images/events/fitness.webp; illustrations





views/partials/eventTile.ejs


The tall photo card in "Events near you". Needs: event. Optional: variant ('dark' or 'light'), eager (load the picture straight away). It shows the category and "Free" pills, an info button that opens the date, place, category and organizer over the photo (a <details> element, so it works without JavaScript), the title with a tick, two lines of description, the date and time, and a Register button.




  • Register opens the event's own page, where joining already handles every case (logged out, full, past, volunteering).


Used byviews/home.ejsUsesviews/partials/eventImage.ejs; CSS classes ev-shell, ev-card, ev-badge, ev-info, ev-body, ev-join
