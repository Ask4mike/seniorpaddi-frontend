Chapter 10How to change anything: recipes

Copy-and-follow instructions for the changes people make most often. Each recipe says which files to open, shows the code before and after, and how to check it worked.

Before every recipe
  1. Make a branch so your work is separate and easy to undo: git checkout -b my-change.
  2. Run the site with npm run dev (and npm run dev:css in a second terminal if you will touch styles).
  3. When done, run npm test if you changed anything in src/.

Recipe 1: Change text on a page

Open: locales/en.json and locales/yo.json. Almost no text is typed straight into the templates; each sentence has a key.

  1. Find the words you want to change. Search the whole project (VS Code: Ctrl+Shift+F) for part of the sentence, for example Free to use. You will find it in locales/en.json: 
    2. 
  
  2. Change the text after the colon. Keep the quotes and the comma at the end.
    
    "home.tagline": "Free community events and friendship for people over 60 in Ibadan.",
    3. 
  
  3. Change the same key in locales/yo.json (or ask a Yorùbá speaker to). If you leave it, Yorùbá users keep the old Yorùbá text.
    4. 
  
  4. Save. With npm run dev the site restarts by itself. Refresh the page.
    5. 



Button labels and headings work the same way: the log-in button is "login.submit", the hero headline is "home.hero_title" plus "home.hero_highlight". To find which key a page uses, open its template and look for t('...').


Warning
JSON is strict: every line but the last needs a comma, and text must be inside straight double quotes. One missing comma stops the site from starting with SyntaxError: Unexpected token in locales/en.json. Some keys contain {name}-style gaps (e.g. {min}); keep those exactly as they are.


Check: refresh the page in English, press the language button, check Yorùbá.



Recipe 2: Change colours, fonts and spacing


Site-wide


Open: src/styles/input.css, the @theme block.




After (a teal brand colour instead of indigo):


--color-primary: #1f7a5f; /* teal */
--color-primary-dark: #175e49;


Then npm run build:css and refresh. Every bg-primary, text-primary and button that uses it changes. Check contrast with node docs/ui-revamp/tools/contrast.mjs: text must stay easy to read.


Text size: the base size is in @layer base (html { font-size: 112.5%; } = 18px). Raising it makes everything bigger. Font: replace the Outfit file and the @font-face/--font-sans lines; check that Yorùbá accents still display.



One section only


Change the classes in that section's template, or its component class in input.css. For example, the hero's soft background is set on .hero-stage:




After (a plain warm cream background):

  @apply relative isolate mx-2 mt-2 flex flex-col overflow-hidden rounded-[2rem] text-charcoal sm:mx-3 sm:mt-3 md:rounded-[2.5rem];

For spacing inside one part of a page, edit the Tailwind classes in the template: in views/home.ejs, the "Events near you" section is class="mx-auto max-w-6xl px-4 py-10"; changing py-10 to py-16 gives it more space above and below. Check: rebuild the CSS, refresh, and look at a phone-size window too (in the browser: F12, then the phone icon).

Recipe 4: Add, remove or rename a field on Log in or Create account


A form field touches up to five places: the template (the box), the words (label and hint), the route (reading and checking it), the model (what is saved) and sometimes a migration (a new database column). Example: an optional "Area of Ibadan" box on Create account. The Users table already has an area column (seniors fill it in Settings), so no migration is needed.


    
  
  1. Template, views/auth/signup.ejs: add a field after the email field, using the shared text box:
    
    <div class="field">
  <label for="area"><%= t('settings.area') %></label>
  <%- include('../partials/ui/textInput', { id: 'area', name: 'area', value: values.area || '', icon: 'fa-location-dot' }) %>
</div>
    
    (It reuses the existing label key settings.area; add a new key to both locale files if you want different words.)
    2. 
  
  2. Route, src/routes/public.js, POST /signup. Today it reads these values:
    
    
    Add area: (req.body.area || '').trim(), to that object, and add area: values.area || null, inside User.create({ ... }) a few lines further down.
    3. 
  
  3. Check rules (optional): add a line such as if (values.area.length > 80) errors.area = req.t('...') next to the other checks, and show errors.area under the box like the other fields do.
    4. 
  
  4. Check: create a test account with an area, then open My account → Settings: the area is filled in. Run npm test.
    5. 



A brand-new piece of information (no column yet) also needs Recipe 8. Removing a field: delete it from the template, the route's values, its checks and User.create; if it was required by the database (allowNull: false), it needs a migration too. Renaming: change the label in locales/ only; renaming the name attribute means changing the route to read the new name.


Important
Log in is checked by phone number and password only (POST /login). Adding a field there means deciding what the server should do with it in router.post('/login', ...). The project's tests post these forms directly, so run npm test after any change to them.

Recipe 6: Add an event, or change how event cards show data


Adding an event is not a code change: log in as staff, go to Organizations (add the host if it is new), then Events → Add event (/admin/events/new). It appears on Home and Find events as soon as it is saved, as long as it is published and in the future. For lots of sample events on your own computer, edit and run npm run seed:local (this wipes your local data).


Changing a card: open views/partials/eventTile.ejs. Every field of the event is available as event.something (the list is in src/models/event.js), and its host as event.Organization. For example, to show the place under the title, after the description line:




add:


<% if (event.locationText) { %><p class="ev-muted mb-3 text-base"><i class="fa-solid fa-location-dot" aria-hidden="true"></i> <%= event.locationText %></p><% } %>


Notice the if: some fields can be empty, so always check before printing. To show more than 4 events on Home, change limit: 4 in the Home route in src/routes/public.js. Check: refresh Home with demo data loaded.

Recipe 8: Change the database: add a column


Example: add an optional emergencyContact to Users. You need two things: a migration (changes the real table) and a model change (tells Sequelize about it).


    
  
  1. New migration file in src/migrations/. The name must start with a date and time later than the newest one (20261003000001-...), e.g. 20261020000001-add-emergency-contact.js. Model it on the existing ones, which look like this:
    
    
    Your file:
    
    'use strict';

module.exports = {
  async up(queryInterface, Sequelize) {
    await queryInterface.addColumn('Users', 'emergencyContact', { type: Sequelize.STRING });
  },

  async down(queryInterface) {
    await queryInterface.removeColumn('Users', 'emergencyContact');
  }
};
    2. 
  
  2. Model, src/models/user.js: add emergencyContact: DataTypes.STRING, next to area: DataTypes.STRING,.
    3. 
  
  3. Restart the site. On start-up src/services/migrate.js runs the new file once and prints Database updated: 1 change(s) applied. (Or run npm run db:migrate.)
    4. 
  
  4. Then use the new column in a form (Recipe 4) and in src/routes/account.js (settings) as needed.
    5. 



Warning
Never edit a migration that has already run on the live database: it will not run again, so your change is silently ignored there. Always add a new file. Removing or renaming columns can lose data: back up first (Recipe 11). npm run db:reset undoes every migration, deleting all data; only use it on a throw-away local database.

  1. Check it is well known and maintained (its npmjs.com page: weekly downloads, last update) and that you really need it.
    2.

    3. 
  
  3. Check that package.json and package-lock.json both changed. Commit both, never node_modules/.
    4. 
  
  4. Use it with const thing = require('package-name'); and run npm test.

  5. On Render, the next deploy runs npm install automatically (buildCommand in render.yaml).

Recipe 10: Change settings or the port


Open: .env. Change or add a line, for example PORT=3001, save, then stop (Ctrl+C) and start the site again: settings are only read at start-up. The site is now at http://localhost:3001, and APP_URL follows automatically unless you set it yourself. On the live site, change settings in Render (the service → Environment); Render restarts the site for you. Chapter 4 lists every setting.



Recipe 11: Undo a mistake safely



  
SituationCommand

  
    
See what you changedgit status (which files), git diff (which lines)

    
Throw away changes to one file (not committed yet)git restore views/home.ejs

    
Put all changes aside for latergit stash (bring them back with git stash pop)

    
Undo a commit you already made (keeps history)git revert <commit-id> (find the id with git log --oneline)

    
Abandon a whole experimentgit checkout main, then git branch -D my-change

    
Back up the local database firstpg_dump -U postgres seniorpadi > backup.sql (restore: psql -U postgres seniorpadi < backup.sql)

  



Warning
git restore and git branch -D throw work away for good. Commands with --force or reset --hard can lose work too; avoid them unless you are sure. Neon keeps its own backups of the live database (see its dashboard).
