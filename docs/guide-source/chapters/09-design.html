Chapter 9The design and image system

How SeniorPadi gets its look: one stylesheet you edit, a set of named colours, one font, shared component classes, and a small folder of pictures.

How the styles are organised

There is exactly one stylesheet you edit: src/styles/input.css (about 1,560 lines). Tailwind reads it, scans every template in views/ and script in public/js/ for class names, and writes the finished file public/css/main.css, which the header loads on every page.

Part of input.cssWhat lives there
@import and @source (top)Load Tailwind and say which files to scan.
@font-faceThe Outfit font from public/fonts/outfit-variable.woff2.
@theme { ... }Design tokens: named values for the font, text sizes and every colour. A token named --color-primary automatically creates classes such as bg-primary, text-primary and border-primary.
@utility blocksA few custom one-job classes (fluid header text, entrance delays).
@layer baseRules for plain HTML tags: the 18px base text size, headings, links, focus outlines.
@layer componentsThe shared pieces, each a class: buttons (.btn-primary, .btn-glow, .btn-white), cards, chips, alerts, form fields, pop-ups, the auth pages, the hero and the event cards.
@media blocks (end)Responsive rules, hover-only effects, and prefers-reduced-motion (see below).
Warning

Never edit public/css/main.css. It is rebuilt from input.css and your change would be lost. After editing input.css (or adding a new class name to a template) run npm run build:css, or keep npm run dev:css running while you work.

The colours were chosen and measured for strong contrast, which matters for older eyes. docs/ui-revamp/palette.md lists the measured contrast of each pair, and node docs/ui-revamp/tools/contrast.mjs re-checks them. If you change a colour, run it again.



Font, text size and spacing


    
  
  • One font: Outfit, for everything (--font-sans). It includes the Yorùbá accented letters.
    • 
  
  • Big base size: the page root is 18px (html { font-size: 112.5% } in @layer base), so 1rem = 18px. The text-size tokens are set so nothing is smaller than about 16px.
    • 
  
  • Spacing uses Tailwind's normal scale in the templates: p-4 is padding of 1rem, gap-6 a gap of 1.5rem, mt-2 a small top margin.
    • 
  
  • Tap targets are at least 48px tall (min-h-12) so they are easy to press.
    • 




Responsive rules (phones to large screens)


Tailwind classes can start with a screen-size prefix: md: means "from 768px wide", lg: "from 1024px", xl: "from 1280px". Without a prefix, a class applies to phones and up. So grid gap-4 md:grid-cols-3 is one column on a phone and three on a tablet or computer. On phones the main menu moves to a bar at the bottom of the screen (partials/seniorNav.ejs with placement: 'bottom').

Making sure browsers load the new stylesheet


Browsers keep copies of files to save data. The header loads the stylesheet as /css/main.css?v=ui5; the ?v=ui5 part is a version label. On the live site, after a style change, raise it (ui6) in views/partials/header.ejs so everyone's browser fetches the new file. The scripts have the same kind of label (?v=ui1).

How pictures are referenced


Anything in public/ is served from the root of the site, so public/images/events/faith.webp is /images/events/faith.webp in a template. Event pictures always go through one partial, which picks the uploaded photo or the category cover:




    
  
  • <picture> with a <source type="image/webp">: browsers that understand WebP get the smaller file; the rest get the JPG.
    • 
  
  • loading="lazy": pictures below the screen load only when you scroll to them (saves data). eager is for pictures visible straight away.
    • 
  
  • width and height stop the page jumping while the picture loads.
    • 
  
  • alt="" marks a picture as decoration that screen readers skip; meaningful pictures get a description from locales/ (the hero uses home.hero_photo_alt).
    •

A component class is just a bundle of Tailwind classes with a name. The pink button, for example:




    
  
  • @apply pulls in ordinary Tailwind classes: full width, very rounded (rounded-full), pink background, white text.

  • hover:bg-rose-600: a slightly darker pink under the mouse.

Things to know
The hero's top bar still has the class name on-yolk (in views/home.ejs and input.css), left over from when the hero was yellow. It works fine on the soft background; the name is just out of date. DESIGN-NOTES.md explains every design decision in detail.



What you learned

    
  
  • Edit src/styles/input.css, then npm run build:css. Never edit main.css.
    • 
  
  • Colours, font and sizes are named tokens in @theme; components are named classes in @layer components.
    • 
  
  • Pictures live in public/images/, are shown as /images/..., and must be recorded in IMAGE_CREDITS.md.
    • 



Try it yourself
