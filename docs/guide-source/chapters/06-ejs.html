Chapter 6EJS explained for beginners

Every page you see on SeniorPadi starts life as an EJS template in views/. Once you can read EJS, you can change almost any page.

What EJS is, and why it exists

A plain HTML file always shows the same thing. But SeniorPadi's pages change: your name appears in the greeting, the list of events comes from the database, an error message appears only when something went wrong, and every word can be English or Yorùbá.

EJS (Embedded JavaScript) solves this. An EJS file is ordinary HTML with a few special tags, the "holes". When a route asks for a page, the server runs the template, fills every hole with real data, and sends the finished HTML to the browser. The browser never sees the EJS tags.

An everyday picture

An EJS template is like a printed form letter: "Dear ____, your appointment is on ____." The route is the clerk who fills in the blanks before posting it.

The four EJS tags used in this project

A count of every template in views/ shows SeniorPadi uses exactly four kinds of tag. Each starts with <% and ends with %>.

TagNameWhat it doesUsed
<%= x %>Output (escaped)Prints the value of x into the page, made safe: characters like < are turned into harmless text.917 times
<%- x %>Output (unescaped)Prints x exactly as it is, HTML and all. Used for include(...) and for HTML the server built itself.145 times
<% code %>ScriptletRuns JavaScript but prints nothing: if, loops, setting a variable.442 times
<%# note %>CommentA note for people reading the template. It is removed completely and never reaches the browser.95 times

1. Output, escaped: <%= %>

This is the tag you will use most. In the log-in page, the heading prints a sentence from the language files:



    
  
  • t('auth.welcome_back') looks up that key in locales/en.json (or yo.json) and returns the sentence. <%= prints it.

  • The class names (text-3xl, text-muted) are ordinary HTML and are styled by Tailwind (chapter 9).

Important: why "escaped" matters
If a senior typed <script> as their name, <%= %> prints it as harmless text instead of running it. This stops a classic attack called XSS (cross-site scripting). Always use <%= %> for anything a person typed.



2. Output, unescaped: <%- %>


Use it only for HTML you trust, and above all for includes (next section). The QR code partial uses it to print an SVG picture that the server drew itself (src/services/qr.js):





3. Scriptlet: <% %>


Runs JavaScript without printing. The opening and closing braces of an if or a loop each sit in their own scriptlet, with ordinary HTML between them. Here the log-in page shows an error box only when there is an error:




    
  
  • <% if (error) { %>: "if there is an error, include the next lines".
    • 
  
  • <%= error %>: print the message.
    • 
  
  • <% } %>: the end of the if. Forgetting it is the most common EJS mistake.
    • 



Scriptlets can also set up variables at the top of a template. The event card works out which look to use:




    
  
  • typeof variant !== 'undefined' asks "was I given a variant?". If not, it uses 'dark'.
    • 
  
  • event.tTitle || event.title: use the Yorùbá title if there is one, otherwise the original.
    • 




4. Comment: <%# %>




Comments explain why a template is built the way it is. The project uses them a lot, so read them: they are often the best documentation.



How the server sends data to a view


A route calls res.render(name, data). The name is a path inside views/ without .ejs; the data is a JavaScript object whose keys become variables in the template.

Partials: reusing pieces


A partial is a small template meant to be placed inside other templates. SeniorPadi keeps them in views/partials/. You place one with include, always inside <%- %> (the dash, so its HTML is not escaped):




    
  
  • The path is relative to the current file: login.ejs is in views/auth/, so ../partials/ goes up one folder.
    • 
  
  • The object { id: 'password', ... } gives the partial its own variables. Inside passwordInput.ejs, id is 'password'.
    • 
  
  • A partial also sees everything the page sees (t, currentUser and so on).
    • 




The "layout": header and footer


Many frameworks have one layout file that wraps every page. SeniorPadi does the same job with two partials: every page starts with include('partials/header') and ends with include('partials/footer'). The header opens <html>, <body> and <main>; the footer closes them. That is why one change in header.ejs changes every page.


The header changes shape depending on what the page passes it:

Common beginner mistakes



  
MistakeWhat happens, and the fix

  
    
Forgetting a closing <% } %>The page fails with an error like Unexpected token or missing ) after argument list. Count your opening and closing braces.

    
Using a variable the route didn't passReferenceError: x is not defined. Pass it in res.render, or check it with typeof x !== 'undefined' as the partials do.

    
<%= include(...) %> (equals instead of dash)The page shows raw HTML code as text. Use <%- include(...) %>.

    
<%- %> on something a user typedA security hole (XSS). Use <%= %>.

    
Wrong include pathCould not find the include file. Paths are relative to the current template.

    
Wrong name in res.renderFailed to lookup view "auth/logn". The name is the path inside views/ without .ejs.

    
Typing English text straight into a templateIt works, but Yorùbá users see English. Add a key to both locales/ files and use t('your.key').

    
Expecting EJS code to run in the browserIt runs once, on the server, before the page is sent. For things that react to clicks, use a script in public/js/.

    
A new POST form with no _csrf fieldThe error "This page was open too long...".  Add <input type="hidden" name="_csrf" value="<%= csrfToken %>">.

  




What you learned

    
  
  • <%= %> prints safely, <%- %> prints raw HTML (for includes), <% %> runs code, <%# %> is a comment.
    • 
  
  • res.render('folder/name', { ... }) picks the template and gives it data; res.locals adds data to every page.
    • 
  
  • Every page is header partial + its own content + footer partial.
    • 



Try it yourself
In views/partials/flash.ejs, the icon for a success message is fa-circle-check. Change it to fa-face-smile, save, then create a new test account: the green "Welcome" message on the next page now has a smiley. Change it back afterwards. You just edited a partial that every page uses.
