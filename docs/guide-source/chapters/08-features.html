Chapter 8How the main features work, end to end

Each feature as a numbered journey, naming the exact file at every step.

Creating an account

  1. GET /signup → src/routes/public.js renders views/auth/signup.ejs with empty errors and values. If the visitor came from an event's Register button, a hidden registerEventId field remembers it.
  2. In the browser, public/js/phone-input.js keeps the phone box to digits and public/js/ui.js checks that "Confirm password" matches.
  3. POST /signup passes signupLimiter (5 an hour), then every field is checked: 
    
    A phone number or email already in use is refused too.
    4. 
  
  4. With errors, the same page comes back (status 400) with one message under each wrong field and the typed values kept.
    5. 
  
  5. User.create(...) saves the account with a bcrypt password hash; req.session.userId logs them in; a "Welcome" flash message is set.
    6. 
  
  6. finishAuth: if they were registering for an event, confirm the phone first (/verify) or register straight away; otherwise go to the welcome video (/onboarding).
    7. 




Logging in and out


    
  
  1. GET /login → views/auth/login.ejs.
    2. 
  
  2. POST /login passes loginLimiter (10 tries per 15 minutes); normalizePhone() tidies the number and explains exactly what is wrong if it is invalid.
    3. 
  
  3. User.findOne and bcrypt.compare. On failure one general message is shown, never saying which part was wrong.
    4. 
  
  4. On success:
    
    
    Staff go to /admin; a senior finishes any event registration, sees the welcome video if never seen, or returns to the page they wanted.
    5. 
  
  5. src/middleware/locals.js loads the user on every later request; the cookie lasts 30 days.
    6. 
  
  6. Log out: public/js/ui.js asks "Log out?" (partials/confirmLogoutModal.ejs), then POST /logout ends the session and goes to /login.
    7. 




Confirming the phone number


    
  
  1. Joining an event or messaging needs a confirmed phone. needsContactCheck() in src/routes/verify.js remembers what they were doing and sends them to /verify.
    2. 
  
  2. POST /verify/send → src/services/verification.js sends a 6-digit code by SMS (in dry-run mode it is printed in the terminal). public/js/otp.js shows six boxes and a 60-second resend countdown.
    3. 
  
  3. POST /verify/check; once confirmed, carryOn() finishes the registration they started.
    4. 




The home page, hero and Events near you


    
  
  1. GET / → src/routes/public.js loads up to 4 upcoming published events with their organization, translates them if needed, and renders home.
    2. 
  
  2. views/home.ejs includes the header with pageLayout: 'hero', draws the hero (own top bar, headline, photo public/images/events/fitness.webp, event count, "Find events" button).
    3. 
  
  3. It loops over upcoming and includes partials/eventTile.ejs per event, alternating dark and light; with none, an empty-state message.
    4. 
  
  4. Each card uses partials/eventImage.ejs (uploaded photo or category cover), a <details> info panel, and a Register link to /events/:id.
    5. 




Finding, filtering and joining events


    
  
  1. GET /events?category=... → src/routes/events.js loads open events, removes full ones and ones already joined:
    
    
    then skips those in req.session.skippedEvents and shows one card (views/events/index.ejs).
    2. 
  
  2. A visitor pressing Register gets the log-in pop-up (partials/loginModal.ejs); after logging in they are registered automatically.
    3. 
  
  3. A senior posts to /events/:id/register; registerAndNotify() calls capacity.register(), which locks the event and checks it is open and not full:
    
    4. 
  
  4. A Registration with a ticket number is saved, the SMS/email confirmation is sent, and the "You're registered" pop-up opens.
    5. 
  
  5. Cancel from /registrations (src/routes/account.js); reminders go out at 8:00 (src/services/cron.js); staff mark attendance through src/services/attendance.js.
    6. 




What you learned

    
  
  • Sign up and log in live in src/routes/public.js; the session remembers userId.
    • 
  
  • Home's cards come from one query and eventTile.ejs; Register leads to the event page.
    • 
  
  • Every registration goes through capacity.register(), which cannot overbook.
