Chapter 4Project setup, step by step

This chapter takes you from an empty computer to SeniorPadi running in your browser. Follow the steps in order. Where Windows, macOS and Linux differ, each is shown.

Tip: what a terminal is

A terminal is a window where you type commands instead of clicking. On Windows use PowerShell or the terminal inside VS Code (Ctrl+`). On macOS use Terminal. On Linux use your terminal app. Type a command, then press Enter.

1. Install the tools

ToolWhyHow
Node.js 20+ (LTS)Runs the server. npm comes with it.Download the LTS version from nodejs.org and install it. Check with node -v (should say v20 or higher).
GitDownloads the code and keeps its history.Windows: git-scm.com. macOS: run git --version and accept the offer to install. Linux: sudo apt install git.
PostgreSQLThe database.Windows: the installer from postgresql.org (remember the password you choose for the postgres user). macOS: Postgres.app, or brew install postgresql. Linux: sudo apt install postgresql. Or skip it and use a free Neon database online.
A code editorTo read and edit files.Visual Studio Code (code.visualstudio.com) is a good free choice.

2. Get the code

In a terminal, go to the folder where you keep projects and clone (download) the repository:

git clone https://github.com/Ask4mike/seniorpaddi-frontend.git
cd seniorpaddi-frontend
Things to know

This is the repository the project's Git is connected to (its origin). README.md mentions a different address (Otani-ibe/SeniorPadi_Capstone), which looks like an earlier home of the project. Use whichever one you were given access to.

3. Install the packages

npm install

This reads package.json and downloads everything into a new node_modules/ folder. It can take a few minutes the first time. You only need to run it again when package.json changes (for example after pulling someone else's work).

4. Create the database

Skip this if you will use Neon. Otherwise make an empty database called seniorpadi. The tables are created for you later.

# macOS, Linux, or Windows when psql is on your PATH:
psql -U postgres -c "CREATE DATABASE seniorpadi;"
# Linux, if psql says "role postgres does not exist" or asks for a password you never set:
sudo -u postgres psql -c "CREATE DATABASE seniorpadi;"

On Windows, if psql is "not recognized", use its full path, for example & "C:\Program Files\PostgreSQL\17\bin\psql.exe" -U postgres -c "CREATE DATABASE seniorpadi;" (change 17 to your version), or create the database by right-clicking Databases in pgAdmin, which is installed alongside PostgreSQL.

5. Create your settings file (.env)

Create a new file called exactly .env (with the dot, no other extension) in the main project folder, next to package.json. Paste this in and replace the placeholder values:

# which database: local (PostgreSQL on this computer) or neon
DB_TARGET=local
LOCAL_DATABASE_URL=postgresql://postgres:YOUR_DB_PASSWORD_HERE@localhost:5432/seniorpadi
# NEON_DATABASE_URL=postgres://YOUR_NEON_USER:YOUR_NEON_PASSWORD@YOUR_NEON_HOST/neondb

SESSION_SECRET=YOUR_LONG_RANDOM_TEXT_HERE

# the first staff (admin) account, created on first start
ADMIN_NAME=Your Name
ADMIN_PHONE=08000000000
ADMIN_PASSWORD=YOUR_ADMIN_PASSWORD_HERE

# print texts and emails in the terminal instead of sending them
NOTIFY_DRY_RUN=true
SUPPORT_PHONE=08000000000
Warning
  • Never commit .env or paste it anywhere public. It holds passwords. It is already listed in .gitignore, so Git ignores it.
  • If your database password contains @, : or /, it must be "URL-encoded" in the address (for example @ becomes %40).

6. Check the database connection

npm run db:check

This runs src/scripts/checkDb.js, which prints which database the app will use and whether it can reach it. You want to see Connected: yes. If not, chapter 11 lists the usual causes.

7. Start the app

CommandWhen to use it
npm startStarts the site once. Uses whatever DB_TARGET says in .env.
npm run devSame, but restarts by itself when you save a .js or .json file. Best while working.
npm run dev:local / dev:neonLike dev, but forces the local or Neon database whatever .env says.
Double-click start-windows.batWindows shortcut: checks Node, installs packages the first time, then runs npm start.

The first start creates every table and your admin account. A good first start looks like this:

Starting SeniorPadi...
  Database connected (localhost)
  Database updated: 10 change(s) applied
  Added the default welcome guide text
  Created the first admin account (08000000000)
  ! Brevo is not set up. Texts and emails are printed in the log instead of sent.
  ! Cloudinary is not set up. Picture, ID and video uploads are switched off.
  ! Google Translate is not set up. Menus are still in Yorùbá, but event text stays in English.
SeniorPadi is running at http://localhost:3000

The lines with ! are warnings, not errors: the site works without those services.

8. Add demo data (optional)

npm run seed:local

This wipes your local database and fills it with sample organizations, events and users (src/scripts/seed.js). It refuses to wipe a Neon database unless you use npm run seed:neon on purpose. The README lists the demo accounts: every one uses the password password123, and the demo admin's phone number is 08000000001.

9. Open it in the browser

  • The site: http://localhost:3000
  • Log in: http://localhost:3000/login. Staff are sent to the dashboard at /admin after logging in.
  • Health check: http://localhost:3000/health

localhost means "this computer". Only you can see it; nothing is on the internet.

10. Stop and restart

  • Stop: click in the terminal that is running the site and press Ctrl+C (on macOS too). If asked "Terminate batch job (Y/N)?", type Y.
  • Start again: run the same command (npm run dev). Pressing ↑ in the terminal brings back the last command.
  • After changes, see the table below.
You changed...What to do
A .js file in src/, or a .json file (like locales/en.json)With npm run dev: nothing, it restarts itself. With npm start: stop and start.
An .ejs file in views/Just refresh the browser. (On your computer, Express reads templates fresh every time.)
src/styles/input.css, or you added new class names in a templateRun npm run build:css, then refresh. Or keep npm run dev:css running in a second terminal: it rebuilds on every save.
A file in public/ (a script or picture)Refresh. If the old version still shows, do a hard refresh: Ctrl+F5 (Windows/Linux) or Cmd+Shift+R (macOS).
.env or package.jsonStop and start. After a package.json change, run npm install first.

Looking at pages without a database

The project has a preview server that shows every page using made-up sample data. It is handy for design work, or if your database is not ready yet. Nothing is saved and forms do not submit.

node docs/ui-revamp/tools/preview-server.mjs
# then open http://localhost:4100/__pages   (Windows: or double-click docs/ui-revamp/tools/start-preview.bat)

Common setup errors

You seeWhat it means and the fix
'node' is not recognized / command not found: nodeNode.js is not installed, or the terminal was open before you installed it. Install it, then open a new terminal.
The database address is missing.No .env, or it is in the wrong folder, or the *_DATABASE_URL for your DB_TARGET is empty.
Database not ready (ECONNREFUSED), then Is Postgres started?PostgreSQL is not running. Start it (Windows: Services app → "postgresql" → Start; macOS: open Postgres.app; Linux: sudo service postgresql start).
(28P01) "password is wrong"The password inside the database address is wrong.
database "seniorpadi" does not existDo step 4.
EADDRINUSE: address already in use :::3000The site is already running in another terminal. Stop that one, or set PORT=3001 in .env.
Pages show with no stylingRun npm run build:css.
npm install fails on bcryptUsually an old Node version. Install the current Node LTS, delete node_modules, run npm install again.
Things to know
  • start-windows.bat tries to copy a file called .env.example when .env is missing, but the project has no .env.example. On a fresh copy the batch file will open an empty Notepad. Create .env by hand as in step 5.
  • The start-up message says uploads are "switched off" without Cloudinary, but src/services/cloudinary.js actually saves them on your computer instead (public/uploads/, storage/ids/). The warning is out of date, not the uploads.
What you learned
  • Install Node.js, Git and PostgreSQL; clone; npm install; create .env; npm run dev.
  • The app creates its own tables and first admin account.
  • Ctrl+C stops it. npm run dev restarts by itself; CSS changes need npm run build:css.
Try it yourself

Run npm run seed:local, start the site, and log in as the demo admin (phone 08000000001, password password123). Then log out and sign up as a brand-new senior with your own made-up details.
